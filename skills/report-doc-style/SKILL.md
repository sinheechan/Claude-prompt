# 공식 문서 스타일

## 문체

- **개조식**으로 쓴다. 문장 끝은 명사형 종결: "~함", "~임", "~예정", "~완료".
  - 좋음: "레이더 항적 데이터 전처리 파이프라인 구축 완료"
  - 피함: "레이더 항적 데이터 전처리 파이프라인을 구축했습니다."
- 한 항목 = 한 가지 사실. 두 줄을 넘기면 하위 항목으로 나눈다.
- 주관적 표현(매우, 획기적인, 혁신적인) 대신 수치로 말한다.
  - "정확도 대폭 향상" → "분류 정확도 87.2% → 93.5% (6.3%p 향상)"

## 기호 체계

```
1. 대제목
  가. 중제목
    1) 소제목
      가) 세부 항목
        - 나열
```

## 구성 원칙

- 각 장은 **현황 → 문제/필요성 → 해결 방안 → 기대 효과** 순서를 기본으로 한다.
- 성과는 정량(수치) + 정성(의미) 두 줄로 쓴다.
- 일정은 표로, 월 단위 `'26.05 ~ '26.11` 형식.
- 약어는 처음 나올 때 풀어쓴다: "잔여수명(RUL, Remaining Useful Life)".

## 표

- 표 제목은 표 위에: `<표 3> 단계별 추진 일정`
- 그림 제목은 그림 아래: `[그림 2] 데이터 파이프라인 구성도`
- 단위는 제목 옆 괄호에: `(단위: 건, %)`

## 보안·표현 주의

- 발주처, 장비명, 내부 수치 등 민감 정보는 사용자가 준 표현만 쓰고 추측해서 채우지 않는다.
- 빈칸은 `[○○ 입력]`으로 표시해 사용자가 채우게 한다.

## 더 필요할 때

- 장별 뼈대가 필요하면 `references/template.md`를 읽는다.
