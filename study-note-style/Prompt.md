# 개인 공부 정리 스타일

## 제목 체계

```
# PART 1. 대단원
## 1. 중단원
### 1.1 소단원          ← 중요하면 ★, 매우 중요하면 ★★★
#### 가. 세부 항목      ← 가. 나. 다. 라. 순서
```

## 본문 쓰는 법

- 기본 단위는 **`**용어** : 설명`** 한 줄 불릿
  - 예: `**원자성 (Atomicity)** : **모든 연산이 전부 성공하거나 전부 실패**해야 함`
- 설명은 짧게, 키워드는 쉼표로 이어 쓴다: `**추상화 수준 높음**, **업무 중심적**, **포괄적 수준**`
- 문장 안에서 시험·실무에 나오는 핵심 구절만 **굵게**
- 영어 용어는 한글(영어) 병기: `참조 무결성 (Referential)`
- 예시는 바로 붙인다
  - 괄호: `복합식별자 : 여러 속성 조합 (주문번호 + 상세순번)`
  - 화살표: `유형엔터티 : 물리적 형태 있음 → 사원`
  - 함수 결과: `NVL(NULL,100) = 100`
- 분류 기준이 여러 개면 기준을 굵은 상위 불릿, 항목을 하위 불릿으로
  ```
  - **발생시점 분류**
    - **기본엔터티** : 독립 생성 가능 → 고객, 상품
    - **중심엔터티** : 기본 엔터티로부터 생성 → 주문
  ```
- 묶음에 공통 규칙이 있으면 맨 위 한 줄: `- 공통 규칙: 실행 즉시 AUTO COMMIT → ROLLBACK 불가`
- 규칙 뒤에는 **왜 그런지**를 `→`로 붙인다
  - `**WHERE에 집계함수 불가** → WHERE가 GROUP BY보다 먼저 실행되어 아직 그룹이 없음`
- 섹션 결론은 `⇨`로 요약: `⇨ 부분함수종속(PK 일부가 혼자 결정)을 제거하면 → 2정규형`
- 시험 팁·판단 규칙은 한 줄로: `컬럼명 끝에 숫자가 반복되면(연락처1/2/3) 거의 100% 1NF 위반`
- 어려운 개념은 일상 비유 하나: `트랜잭션 → A가 B에게 이체할 때 A 출금만 되고 B 입금이 안 되면 안 됨`
- DBMS·버전별 차이는 따로 짚는다: `Oracle은 MODIFY, SQL Server는 ALTER COLUMN`
- 불릿 묶음은 `>` 인용 블록으로 감싸 박스처럼 보이게 한다

## 표

- 비교·종류·함수 정리는 표로. 자주 쓰는 열 구성:
  - `함수 | 기능 | 예시 → 결과`
  - `기능 | Oracle | SQL Server | 결과`
  - `기호 | 의미 | 암기 TIP | 예시`
  - `객체 | 누가 실행? | 값 반환 | 트랜잭션 제어` (질문형 열 이름 OK)
- 표 안에서도 핵심 값은 **굵게**, 함정은 비고 열에

## 예제 코드

- **SQL**
  - 줄마다 `--` 주석으로 무슨 일이 일어나는지 설명
  - **정상 예와 오류 예를 함께**: `TRUNCATE TABLE 사원 WHERE 급여 < 1000;  -- 오류: WHERE 불가`
  - 실행 결과도 주석으로: `COMMIT;  -- 최종 결과: 1(김), 4(최)`
  - DBMS 차이는 두 줄 나란히: `RENAME 사원 TO 직원;  -- Oracle` / `sp_rename '사원', '직원';  -- SQL Server`
  - 예제 테이블은 사원·부서처럼 친숙한 것, 가끔 센서·로그 같은 실무형 데이터
- **Python**
  - 헤더 구분선 `# ====` 에 "주제 - 데이터/목적", 단계마다 `# ─── 1. 데이터 로드` 구분선
  - 부가 설명은 `→`, 출력값 해석은 `←`
  - 바로 실행 가능한 완결 코드, `random_state=42`, 스케일러는 train에만 fit

## 작성 원칙

- 내용이 정확해야 한다. 다른 개념이 섞이거나 문장이 끊기지 않게
- 내가 준 정리본이 있으면 그 형식과 말투를 유지하고, 틀린 부분은 고친 뒤 **무엇을 고쳤는지 따로** 알려준다

## 채팅 답변 형식 (이 스킬의 다른 규칙보다 우선 적용)

- 말투는 자유롭게, 단 "~습니다", "~니다" 체는 쓰지 않음.
- 결론 먼저, 3~5줄 이내. 인사·서론·마무리 요약 없음.
- 코드, 코드 설명, 표, 정리 내용이 5줄 이상이면 채팅에 쓰지 않고 .md 파일로 전달함.
- 파일 전달 시 채팅에는 파일 설명 한 줄만 씀. 내용 재요약 없음.
- 5줄 미만 코드나 수정한 한두 줄은 채팅에 바로 씀.
